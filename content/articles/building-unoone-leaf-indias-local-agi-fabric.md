# UnoOne LEAF: A Historical Local-Agent Research Proposal

The June 2026 LEAF article explored a **Local Evolving Agent Fabric** for Indian device, language and connectivity constraints. Its motivation remains useful: make local tools, memory and bounded actions work together without requiring a cloud round trip for every task.

## What the proposal explored

The historical design sketched a local core, a Qwen-based task router, a skill layer, permitted tools, result checking and a memory ledger. A proposed “Sleep Learning Loop” would evaluate changes to skill prompts against past failures. This was a research direction, not evidence that a deployed agent improved itself every night.

The Qwen-first examples (`qwen2.5:1.5b` and `qwen2.5-coder:1.5b-instruct`) and a 4GB Android target were planning assumptions. They are not a current model recommendation, supported-device list or benchmark. Likewise, the earlier claim that Indian-language fine-tuning was under way needs a dated dataset/training record before it can be stated as fact.

## What the proposed applications meant

The article envisaged document analysis and possible future applications for UnoOne, Sahayaak Seva, UniAssist and KathaKitaab. Those examples do not establish a deployed shared intelligence core, health-record integration or a shipped cross-product learning system.

A useful research evaluation would record the starting build, hardware, task set, failure criteria and results on held-out cases. Improving a prompt on examples already seen is not evidence of general intelligence. Any proposed learning loop needs bounded permissions, human review, regression checks and rollback before use in consequential workflows.

## Current product boundary

[PAI](/private-ai) is the personal private agent implemented through [UnoOne Power](/unoone/power) for Windows and [UnoOne Mobile](/unoone/mobile) for Android. Power is a development build and Mobile is an alpha. Mobile’s current content describes a LiteRT-LM planner with staged activation awaiting device confirmation, not the historical Qwen-first proposal as a verified runtime.

Each device has its own encrypted store. [Phone–desktop continuity](/unoone/sync) is in development; a physical round trip is not yet qualified. Optional online tools can transmit permitted data. Local execution alone is not a guarantee that all data stays on-device.
