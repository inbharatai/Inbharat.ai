## Canonical facts and safe defaults

- **PAI** is the personal private agent. **UnoOne Power** is the Windows development product and **UnoOne Mobile** the Android alpha. The browser console is separate. The historical USB/removable-drive Pocket AI formulation remains research history, not a current consumer offer.
- Local inference, encrypted device-local storage and network actions are different boundaries. Searches, connectors, navigation and confirmed submissions/uploads can send requests and selected data externally. Normal website authentication traffic is not “never sharing credentials”; the agent does not type passwords.
- Mobile agent payment, OTP, password-entry and auto-send classes are **blocked**, not confirmable. The human completes sensitive actions outside the agent. Desktop confirmation-gated forms do not establish Android upload support.
- Pairing protocol implementation/unit tests do not establish a manual two-device workflow. No physical phone–desktop round trip is qualified, manual or automatic. Devices have separate stores.
- “Implemented” means a source implementation with the stated bounded evidence, **not** release qualification. SILT is **Research**; portable Pocket AI is **Historical**. The public evidence label is **Evidence / validation scope**, never a blanket “Verified”.
- No public UnoOne installer or free UnoOne offer is established. The separate web-console trial is not UnoOne pricing.
- Fifteen product-directory entries, the application entry points, signature visual compositions, Gita quotation and six-entry featured recognition rail are preserved. Descriptive corrections do not imply every linked product is live or clinically validated.

## Evidence hierarchy

| Level | What it can establish | What it cannot establish |
| --- | --- | --- |
| Repository/source implementation | A described module, contract or UI exists in that source | A successful current physical-device workflow |
| Unit/contract tests | Defined assertions passed on a named revision/environment | Complete security, current device compatibility or user outcomes |
| Historical device run | Recorded scenarios on that build, hardware and date | Current-tree qualification or other devices/languages |
| Current end-to-end qualification | Defined workflow passed with versioned evidence | Untested configurations, universal safety or broad release readiness |
| Release qualification | Package, compatibility, support and distribution checks for a stated audience | Guaranteed absence of defects |
| Research publication/filing | A disclosed proposal or filing record | Runtime performance, granted rights, endorsement or coverage of newer features |

The shared content reports internal engineering evidence inherited from the approved source. This review did **not** inspect proprietary runtime logs or rerun those product tests. Each numerical test statement must retain this scope until owner-approved evidence is published.

## Verification and limitations

Existing visual designs were retained, but changed copy needs parent responsive-render checks.
